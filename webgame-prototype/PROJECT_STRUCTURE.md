# 웹게임 파일 구조

`index.html`은 정적 배포 진입점이며, 기능 코드와 런타임 에셋은 역할 및 스테이지별로 분리한다.

```text
webgame-prototype/
├── index.html
├── app/
│   ├── common/          # 공통 UI, 전체 스타일, 시작·완료 화면 모션
│   ├── stage-1/         # 외출 전 점검 로직, 대사, 안전수칙 카드, 주방 장면
│   ├── transitions/     # 현관문 줌인과 외출·복귀 장면 전환
│   └── stage-2/         # 귀가 후 점검 로직, 대사, 화면 스타일
├── assets/
│   ├── common/          # 음악, 소멍이, 시작·완료 공통 배경
│   ├── stage-1/         # 스테이지 1 런타임 배경과 상호작용 소품
│   ├── transitions/     # 외부 낮·노을 전환 배경
│   ├── stage-2/         # 스테이지 2 런타임 배경과 소품
│   └── masters/         # 원본 품질 제작 에셋(런타임과 분리)
└── tests/               # PC, 키보드, 모바일 및 장면 전환 회귀 테스트
```

## 대사 관리

- 스테이지 1: `app/stage-1/dialogue/somyeongi-dialogue.js`
- 스테이지 2: `app/stage-2/dialogue/somyeongi-dialogue.js`
- 화면 문구를 추가할 때 HTML 또는 장면 스크립트에 직접 작성하지 않고 해당 스테이지 대사 객체에 먼저 추가한다.

## 에셋 배치 규칙

- 두 스테이지에서 함께 쓰는 소멍이·음악·시작 화면 에셋은 `assets/common/`에 둔다.
- 특정 스테이지에서만 쓰는 배경과 소품은 해당 `assets/stage-N/`에 둔다.
- 장면 사이에서만 쓰는 외부 낮·노을 배경은 `assets/transitions/`에 둔다.
- 생성 원본이나 고해상도 보존본은 `assets/masters/`에 두고, 화면에서 참조하는 최적화본과 구분한다.

## 스크립트 로드 순서

1. 스테이지별 대사
2. 스테이지 1 콘텐츠와 공통 UI
3. 스테이지 1 장면
4. 장면 전환
5. 스테이지 2
6. 메인 게임 오케스트레이션

정적 호스팅과 `file://` 실행을 유지하기 위해 모든 경로는 `index.html` 기준 상대 경로를 사용한다.
